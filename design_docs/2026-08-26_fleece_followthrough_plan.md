# Plan: Fleece follow-through

**Date:** 2026-08-26
**Status:** Complete. Implementation, focused verification, and the headed
retained-document activation and indication receipt are green.
Documentation landed first, followed by the three parallel packets: retire the
`genet-extract` shim, activate Text Fragments in the retained Genet host, and
replace Mere's manifest-only Fleece dependencies with real calls or remove them
from the wrong layer.

## Why this plan exists

Fleece 0.4 is complete and published. Its extraction, anchor, structured-data,
metadata, and table contracts are not reopened here. The closeout audit found
three pieces of follow-through that sit outside that release but are concrete
enough to implement now:

1. the original reader scope allowed `genet-extract` to remain as a compatibility
   shim for one release, but Genet 0.4 still carries and publishes it;
2. Fleece generates URL Text Directives, while Genet's retained document host
   implements only element-ID fragment scrolling; and
3. several Mere crates name Fleece as a future receipt without calling it.

This plan converts those three tails into bounded work. It does not turn Fleece
into a navigator, fetcher, store, annotation service, or product shell.

## Verified starting point

### Findings, 2026-08-26

- Genet `42941fe18bf` contains Fleece 0.4 and the later retained-document find
  seam. `LiveryDocument` can find and select a retained text range, and existing
  fragment handling can scroll to an element ID.
- `components/genet-extract` is a pure wildcard re-export. The only live source
  call found across Genet, Mere, and Turnstone is Mere
  `crates/import/src/web_clip.rs`, which calls
  `genet_extract::extract_main_text`.
- Genet's dependency-cone CI currently asserts that `genet-extract` remains a
  workspace package. That guard now preserves the migration shim rather than
  the intended final architecture.
- Fleece's `text_fragment` function is generation only. No Genet host code
  parses `:~:text=`, applies prefix/suffix matching, selects and scrolls the
  result, or proves that the directive is absent from script-visible URL state.
- Mere's `mere-crawl`, `gazette`, and `mere-eidetic-search` manifests name
  Fleece, but their sources do not call it. Gazette explicitly leaves feed
  polling and the reading room unbuilt. Alembic already removed its placeholder
  dependency until Article-consuming distillation exists.
- Mere's import path already performs real extraction, but does so through the
  obsolete shim. The page-text-to-eidetic-search host path is built; the search
  crate itself should not parse live documents.

## Authority boundaries

- Fleece continues to own render-free extraction and Text Directive generation.
- Genet's retained document/session layer owns navigation-time parsing,
  matching, selection, scrolling, indication, element-fragment fallback, and
  script-visible URL privacy.
- Crawl owns frontier policy and URL resolution. It may ask Fleece for raw links
  from supplied HTML, then resolve and admit them itself.
- Gazette owns polling and stored feed/article state. A narrow HTML-to-Article
  function may land before the poller so the Fleece dependency has a real use.
- Eidetic search consumes extracted text. It does not own DOM parsing and should
  not depend directly on Fleece merely to document a host-side pipeline.
- Alembic remains dependency-free until Athanor actually accepts an Article.

## Packet S: retire `genet-extract`

Migrate the final Mere source call to `fleece::extract_main_text`. Remove the
Mere `genet-extract` workspace dependency, the Genet workspace member and shim
directory, and the CI assertions that require the shim. Repair active prose
that presents the shim as current architecture. Published crate versions remain
available for external users; retirement means Genet stops developing and
publishing new versions, not yanking history.

**Done when:**

- `rg` finds no source or manifest reference to `genet-extract` outside
  historical/archive documentation and lockfile history;
- Mere import tests compile and exercise the same HTML `main_text` behavior via
  Fleece;
- Genet metadata and dependency-cone CI pass without the shim package; and
- current Genet, Mere, and Turnstone manifests resolve without a local or git
  `genet-extract` dependency.

## Packet T: retained-host Text Fragment activation

Add a host-owned parser for the pinned WICG Text Directive shape generated by
Fleece. Preserve any ordinary element-ID fragment independently. Match decoded
start/end text with optional prefix/suffix context against retained logical
text, project the result to the existing retained text-range type, select it,
and scroll it into view. Multiple directives are tried in source order until a
match succeeds. Invalid or unmatched directives fall back to the ordinary
element fragment when one exists.

The navigation/session layer retains the directive as pending activation state
but exposes a URL with the `:~:` directive stripped to page script. This privacy
rule applies before `document.URL` and `Location` are initialized. The first
implementation target is Genet's retained static/scripted document family,
where text frames, selection, and scrolling already exist. Other engine families
must report unsupported rather than claim activation.

**Done when:**

- parser tests cover start-only, start/end, prefix, suffix, percent encoding,
  non-ASCII text, malformed directives, multiple directives, and an ordinary
  element fragment combined with a text directive;
- retained static and scripted fixtures select the intended range and produce a
  scroll change or an explicit already-visible success;
- an unmatched directive preserves element-fragment fallback;
- script-visible URL tests prove `document.URL`, `Location.href`, and
  `Location.hash` omit the directive; and
- a headed retained-document receipt shows activation and indication without a
  second fetch.

## Packet C: make downstream dependencies honest

Implement two narrow real consumers and remove one misplaced dependency:

- `mere-crawl` gets a production helper that accepts fetched HTML, runs Fleece
  over a static DOM, resolves the returned raw links through crawl's existing
  base/scope policy, and enqueues the admitted targets. Its test must use the
  same helper as the runtime seam.
- Gazette gets a reusable supplied-HTML-to-`Article` function with content-type
  gating. Feed polling and reading-room composition remain separate product
  phases, but the function is the exact extraction seam the future poller calls.
- `mere-eidetic-search` drops its unused direct Fleece dependency. Extracted
  text continues to arrive from the already-built host capture path.
- Alembic remains unchanged except for documentation that continues to defer
  Fleece until Article-consuming distillation is real.

**Done when:**

- `rg` finds actual Fleece calls in crawl and Gazette source, with focused tests;
- crawl proves URL resolution, deduplication, host/depth admission, and a
  non-HTML bypass without moving policy into Fleece;
- Gazette proves readable, unreadable, and non-HTML supplied documents without
  fetching or storing inside the extraction helper;
- eidetic-search builds without Fleece in its dependency cone; and
- active Mere docs distinguish these extraction seams from the still-unbuilt
  poller, reading room, and Athanor distillation actor.

## Parallel execution

Documentation lands first. Then the three implementation packets can run in
parallel from pinned remote commits:

| Packet | Agent profile | Owned paths |
|---|---|---|
| S, shim retirement | Luna | Genet `components/genet-extract/**`, dependency-cone CI, focused historical wording; Mere `crates/import/**` |
| T, Text Fragment host | Terra | Genet retained document/session and script-runtime URL seams plus new focused tests |
| C, real consumers | Terra | Mere `crates/crawl/**`, `ports/gazette/**`, `crates/eidetic/eidetic-search/Cargo.toml`, and their active docs |

The integration owner retains both workspace-root manifests, lockfiles,
`design_docs/DOC_README.md`, and this plan. Agents report required root-manifest
edits rather than crossing that fence. Each packet uses a disposable detached
worktree because the shared Mere and Turnstone checkouts may contain unrelated
work.

## Integration gates

1. Run focused packet tests first, with isolated Cargo targets.
2. Run Fleece tests and dependency-cone CI after shim removal.
3. Run retained static/scripted document tests plus the script-visible URL
   privacy matrix after Text Fragment integration.
4. Run Mere import, crawl, Gazette, and eidetic-search tests after root-manifest
   integration.
5. Run the existing Knot selector serializer proof and the Turnstone reader
   checks against the integrated Genet revision when their dirty lanes permit a
   detached clean proof.
6. Refresh each remote immediately before pushing. Replay focused commits on an
   advanced remote and rerun affected gates.
7. Remove every temporary worktree, target, cache, and topic branch after the
   remote ancestry receipt.
